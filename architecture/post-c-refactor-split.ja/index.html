    C refactor 後レイアウト — narrative + simulator + population engine 分割¶

    2026-10-15 〜 2026-10-26 の間、3 本の god-class ファイルが 26 PR の cascade (C1a-C1s + C2a-C2f + C3a-C3e) で属性別モジュールに分解された。 分割後も façade ファイルが全ての移動シンボルを re-export するため、 分割前の全 import path は byte-identical で動作し続ける。本ページは コントリビュータが「特定の挙動が今どこにあるか」を見つけるための 地図である。

    英語版: post-c-refactor-split.md。

    2. C1 — narrative template 分割 (12 section builder + 4 共有 helper)¶

    Façade: clinosim/modules/document/narrative/template_generator.py (分割後 1399 LOC)。以下の全シンボルは façade から re-export される。 歴史的 caller (generator._build_<section>、 TemplateNarrativeGenerator()._compose_<name>()、free function の直接 import) は全て動作し続ける。

    パターン¶

    # template_generator.py (façade)
from clinosim.modules.document.narrative.renderers.section_builders.hpi import (
    build_hpi as build_hpi,
    _build_hpi_core as _build_hpi_core,
)
# ...他 11 本の section builder re-export

class TemplateNarrativeGenerator:
    def _build_hpi(self, ctx):
        # composition_sections.py の generator._build_<section> lookup が
        # 引き続き resolve できるよう薄い lazy-import delegator
        from clinosim.modules.document.narrative.renderers.section_builders.hpi import (
            build_hpi,
        )
        return build_hpi(self, ctx)

    直接 free-function import も動作:

    from clinosim.modules.document.narrative.renderers.section_builders.hpi import (
    build_hpi,

    narrative バグ修正時: template_generator.py の薄い delegator から 該当の renderers/section_builders/<section>.py に辿る。delegator は 2 行の shim で、本体は per-section ファイルにある。

    3. C2 — simulator engine 分割 (setup + dispatch + 4 phase)¶

    Façade: clinosim/simulator/engine.py (分割後 632 LOC)。 run_beta + run_forced は top-level entry のまま。

    抽出モジュール¶

    ファイル 内容 Phase
    clinosim/simulator/_setup.py 9 helper — _load_health_screening_visit_reason、_HEALTH_SCREENING_VISIT_REASON、_HEALTH_SCREENING_VISIT_REASON_FALLBACK、_pediatric_visit_reason、_parse_time_range_bound、_TimeRangeBounds、_activate_cached_person、_derive_time_range_bounds、_load_hospital_ops、_resolve_pop_size、_load_prev_admission_cache C2a
    clinosim/simulator/_dispatch.py 病院イベント dispatcher + overlap 処理 — _find_active_inpatient_record、_find_overlapping_inpatient_record、_verify_no_actual_overlap、_handle_overlap_via_merge、_merge_disease_into_active_encounter、_replay_cached_admission_queue、_DispatchState、_dispatch_hospital_events C2b
    clinosim/simulator/phases/_healthcare_calendar.py _run_healthcare_calendar_phase (年次 scheduler) C2c
    clinosim/simulator/phases/_post_discharge.py _run_post_discharge_phase C2d
    clinosim/simulator/phases/_readmission.py _run_readmission_phase C2e
    clinosim/simulator/phases/_ed_slot.py _run_ed_slot_phase C2f

    なぜこの境界か (原案との差)¶

    C2 前の計画書 ../design-guides/p6-god-function-split-plan.md は phase 名を _run_beta_prepare / _run_beta_month_tick / _run_beta_dispatch_window / _run_beta_writeback と提案していた。 実際の分割は代わりに _setup + _dispatch + 4 本の phase runner を 選択した。これは自然なデータフロー境界 (setup → 月次 dispatch loop → phase runner) により直接 map し、各 phase runner を独立に推論 できる形になる。

    Lazy local import¶

    _chemo.py / _pregnancy.py 下のいくつかは clinosim.locale.loader + clinosim.seeding + clinosim.simulator.perinatal に対し lazy local import を使い PR 間の依存連鎖を解く。これにより python -c "import clinosim.modules.population" が cheap に保たれ、 façade 経由の import サイクルを回避する。

    5. 薄い delegator re-export パターン (全モジュール共通)¶

    全ての抽出モジュールは façade を通して同一形状で配線される:

    # engine.py (façade)
from clinosim.modules.population._chemo import (
    pick_active_chemo_regimen as pick_active_chemo_regimen,
    _chemo_cycle_events as _chemo_cycle_events,
)

    as <name> 形式は 必須 — そうでないと ruff --select F401 が unused import として検出する。as export は re-export を type-checker に可視化し、F401 gate をクリーンに保つ。

    外部 caller:

    # 変更なしで動作 (歴史的 import)
from clinosim.modules.population.engine import pick_active_chemo_regimen

# 権威的 source を直接 import することもできる
from clinosim.modules.population._chemo import pick_active_chemo_regimen

    6. 検証契約¶

    全 extraction PR について以下を pass:

    • Full tests/unit/ suite: 7092 passed、16 skipped、1 xfailed。
    • byte-identical cohort fingerprint: US p=500 seed=42 + JP p=500 seed=17 window 2025-01..04、scripts/engine-fingerprint.sh 経由。branch + origin/master baseline 両方で TOTAL sha256 0184a8b382990915e2e04ca6c94bce2d24e105b39d6be827f705c461f8f621a8。
    • ruff check、ruff format、ruff --select F401,F841、 mypy --strict、vulture --min-confidence 60 — 全 green。

    RNG 消費順の reorder なし: caller 提供の np.random.Generator を 触る helper は sequence をそのまま維持。新サブ RNG が現れる場合 (例: perinatal_delivery_seed(person_id, year)、 chemotherapy_regimen_seed(person_id, cancer_code)) は patient / code 単位の決定論的サブ seed で、master stream を触らない。これにより これらの helper が読む yaml データファイルの編集が無関係な患者の カレンダーに波及することはない。
