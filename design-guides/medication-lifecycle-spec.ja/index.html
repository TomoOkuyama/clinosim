    薬剤のライフサイクル — 仕様¶

    位置づけ: 規範。薬剤をオーダー・保留・投与・中止・処方・再処方・コード化する変更は、すべて本書に従う。従えない変更は、同じ PR で理由とともに本書を改訂する。

    英語版: medication-lifecycle-spec.md。

    関連仕様: - 薬剤の同定(drug_ref, same_drug, has_drug, medication_matches)とコード・名称の解決: code-mapping-and-localization-spec.ja.md §4.1 / §9。 - 乱数と、乱数をずらさない変更: determinism-and-rng-spec.ja.md。

    1. 原則¶

    1. 一つの規則は一か所に。 薬剤に関する各判断は、一つのデータファイルを読む一つの関数が行う。その判断を要するすべての段階が、その関数を呼ぶ。段階とは、入院時・日次ループ・投与記録(MAR)・退院時・在宅薬の有効化・経年履歴・FHIR 出力である。独自の写しを持つ段階は無い。
    2. 記録は一つの経過を語る。 1 薬剤につき有効なオーダーは高々一つ。置き換えられたオーダーは中止され、その投与もそこで終わる。終わった入院のオーダーは退院時に閉じる。投与があるオーダーには必ずオーダーがある。有効なオーダーは投与されているか、されない理由を持つ。
    3. シミュレーションで決め、出力時に導く。 オーダーと投与の事実は CIF に格納する。スナップショットや後の記録に依存する状態は FHIR 出力時に計算する(§6)。例えば、退院処方がまだ有効か、どの処方がそれを置き換えたか、である。
    4. 規則には必ずガードがある。 各規則はそれを強制するテストを示す。テストの無い規則は §8 に挙げる。

    4. 投与¶

    規則 正準コード ガード
    日次ループが置いたオーダーの投与は、オーダーの頻度と患者状態(保留・拒否・頓用の契機)からループ内で作る。 medication_pipeline.py::_generate_mar, generate_prn_administrations, prn_category tests/unit/test_prn_from_state.py, tests/unit/test_prn_inhaler_cadence_1318.py
    血清カリウムが治療閾値以上になると、薬剤を二つの範囲で保留する。hold_classes (ACE 阻害薬・ARB・カリウム保持性利尿薬) は結果が出てから退院まで、hold_while_high_classes (ジゴキシン) は投与前の直近のカリウムが閾値以上である間だけ保留する。保留した投与の理由は、その投与前に結果が出た直近のカリウムとする。オーダーセットは、インスリンと併用するデキストロースを単回投与として別に記録する。溶血したカリウム (flag H* / L*、is_hemolyzed) は、保留の契機にも治療の値にもカリウム履歴の値にもしない。日次ループはその delay_minutes 後に stat の再採血をオーダーし (_redraw_hemolyzed、hemolysis_redraw.yaml)、上限 max_redraws まで繰り返し、治療は再採血の結果に従う (Issue #3452)。 modules/drug_safety/hyperkalemia.py (PotassiumHold.high_at, reason_at, hyperkalemia_treatment_orders)、modules/observation/hemolysis_redraw.py (is_hemolyzed, hemolysis_redraw_rules)、simulator/daily_loop.py::_redraw_hemolyzed。データは modules/drug_safety/reference_data/hyperkalemia_response.yaml、modules/observation/reference_data/hemolysis_redraw.yaml。適用は simulator/daily_loop.py::_respond_to_hyperkalemia と medication_pipeline.py::_generate_mar tests/unit/drug_safety/test_hyperkalemia_response_2981.py, tests/unit/drug_safety/test_hyperkalemia_dextrose_digoxin_3232.py, tests/unit/drug_safety/test_hemolyzed_potassium_redraw_3452.py
    昇圧薬・強心薬を持続投与している間(オーダー時刻から終了時刻まで)は、降圧薬・β遮断薬・利尿薬・硝酸薬の予定投与をすべて「昇圧薬・強心薬の持続投与中」を理由に保留する。経口の昇圧薬と単回投与は保留の契機にならない。バイタルの保留条件(SBP < 90、HR < 50)は、各投与の前に入院中に記録された最新のバイタルで判定する(最初の記録より前だけ入院前の基準値を使う)。その日のバイタルを記録した後に適用する。保留理由は hold_reason_display で記録の言語に表示する。 medication_pipeline.py(vasoactive_infusions, vasoactive_hold_reason, apply_vital_holds, latest_vitals_at)。データ simulator/reference_data/vasoactive_hold.yaml, locale/shared/medication_hold_reasons.yaml。_generate_mar、daily_loop.py、unknown_condition.py で適用 tests/unit/simulator/test_vasoactive_hold_3233.py
    昇圧薬の持続投与は、固定の archetype 日ではなく記録された血圧から開始する。その日のバイタル記録後(その日に死亡が決まる場合は終末期のバイタルも含む)、プロトコルが昇圧薬を持つ入院(その archetype 自身の開始、vasopressors / escalation ブロック、いずれかの archetype の開始)で昇圧薬の持続投与が動いていないものは、その日の平均動脈圧が離脱目標(65 mmHg)未満の記録が 2 回以上あり、いずれも最初の輸液オーダーから 3 時間以上後であるとき、第一選択の昇圧薬を開始する。オーダーは 2 回目の記録の 30 分後に置き、その日の残りの投与は入院エンカウンターと病日から seed を作った別系列の RNG で記録する(入院の乱数列には draw を足さない)。疾患プロトコルの固定日の昇圧薬開始(archetype の treatment_modifications、escalation ブロック)はその日には適用しない。そこに書かれた 2 剤目の昇圧薬(バソプレシン)は、昇圧薬が動いており、その開始後に記録した血圧が目標未満であるときに限り、その日に開始する。 simulator/vasopressor_initiation.py, daily_loop.py (_start_vasopressor_for_hypotension, _start_archetype_treatments, _escalate_treatment); データ simulator/reference_data/vasopressor_initiation.yaml tests/unit/simulator/test_vasopressor_from_hypotension_3332.py
    疾患 YAML で start_antibiotic / start_broad_spectrum_antibiotic (正規の表記。start_antibiotics、antibiotics、broad_spectrum_antibiotic(s) は別名で、YAML では使わない) を宣言する感染性合併症には、発症日に抗菌薬を投与する。complication_actions.yaml が合併症ごとに指定する疾患プロトコル (誤嚥性肺炎・尿路感染症・皮膚軟部組織感染・術後創部感染・二次性細菌性肺炎はその感染症自身のプロトコル、敗血症・腹膜炎・胆管炎・壊死性感染・院内肺炎は敗血症プロトコル) の、当該国の第一選択抗菌薬 (薬剤カタログの抗菌薬クラス、抽選による追加薬は除く) を、発症日 13:00 に薬剤安全性ゲート (アレルギー・相互作用・疾患ルール) を通して発注する。ゲートが第一選択をすべて除外した場合は、プロトコルの alternative_penicillin_allergy の薬を発注する。同じ薬が実行中の場合、および指定できるレジメンがない場合 (腹腔内膿瘍、虫垂断端炎) は発注しない。発症日の投与記録は、受診・病日・合併症から種を決めた副乱数で作る (入院の乱数列から抽選しない)。 simulator/complication_actions.py, daily_loop.py (_start_complication_antibiotic); データ simulator/reference_data/complication_actions.yaml tests/unit/simulator/test_complication_antibiotic_3543.py
